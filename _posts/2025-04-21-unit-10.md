## Core Concepts

### What is Recursion?
- A **recursive method** is a method that calls itself to solve a smaller instance of the same problem.
- Useful for problems that can be broken down into similar subproblems.
- Requires:
  - A **base case**: Stops the recursion.
  - A **recursive case**: Calls the function again with modified parameters.

---

## Basic Syntax

```java
public int factorial(int n) {
    if (n == 0) return 1;       // base case
    else return n * factorial(n - 1); // recursive case
}
```

---

## Important Rules
- **Always define a base case** to avoid infinite recursion.
- Ensure the recursive call **progresses toward the base case**.
- Recursive methods can replace iterative loops but may be less efficient due to call stack overhead.

---

## Types of Recursive Problems

### 1. Mathematical Recursion

Examples:
- Factorial
- Fibonacci sequence
- Power calculations

```java
public int fib(int n) {
    if (n == 0) return 0;
    if (n == 1) return 1;
    return fib(n - 1) + fib(n - 2);
}
```

### 2. String Recursion

Manipulating or analyzing strings recursively.

```java
public String reverse(String str) {
    if (str.length() <= 1) return str;
    return reverse(str.substring(1)) + str.charAt(0);
}
```

### 3. Array Recursion

Solving array-based problems like searching, summing, etc.

```java
public int sum(int[] arr, int index) {
    if (index == arr.length) return 0;
    return arr[index] + sum(arr, index + 1);
}
```

---

## Trace Example: Recursive Sum

```java
public int sumTo(int n) {
    if (n == 1) return 1;
    return n + sumTo(n - 1);
}

System.out.println(sumTo(4));
```

**Call Stack:**
- sumTo(4) = 4 + sumTo(3)
- sumTo(3) = 3 + sumTo(2)
- sumTo(2) = 2 + sumTo(1)
- sumTo(1) = 1 → base case

**Output:**
```
10
```

---

## Common Mistakes to Avoid

- **Missing a base case** → causes StackOverflowError.
- **Wrong recursion direction** → call never reaches the base case.
- **Using `==` for string comparisons** → use `.equals()` instead.
- **Changing original array/string unintentionally** in recursive calls.

---

## Recursive vs Iterative

| Feature        | Recursive                      | Iterative                      |
|----------------|--------------------------------|--------------------------------|
| Approach       | Divide problem into subproblems| Loop with condition            |
| Base case      | Required                       | Not applicable                 |
| Stack usage    | Call stack (uses memory)       | Uses loop, minimal stack usage |
| Readability    | Often simpler                  | Sometimes more efficient       |

## Example Questions

### Question 1:
What will the following code print?

```java
public int mystery(int x) {
    if (x <= 0) return 0;
    return x + mystery(x - 1);
}

System.out.println(mystery(3));
```

**Answer:**
```
6
```

**Explanation:**
- 3 + mystery(2)
- 2 + mystery(1)
- 1 + mystery(0)
- Returns 3 + 2 + 1 = 6

### Question 3:
What is the output?

```java
public void countDown(int n) {
    if (n == 0) return;

    countDown(n - 1);

countDown(3);
```


## Tips for Success

- Clearly define and test your base case first.
- Use diagrams or trace tables to follow the call stack.
- Recursion is best when the problem is **self-similar**.
- Practice tracing recursive functions manually.

## Summary

- Recursion is a powerful technique for solving problems that break down into smaller subproblems.
- Always define a base case.
- Practice writing and tracing recursive functions to build fluency.
- Use recursion thoughtfully: not always the best tool for efficiency but great for clarity.
